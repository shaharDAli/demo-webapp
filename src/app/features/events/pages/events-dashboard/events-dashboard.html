Architecture Concepts

How Multiple Consumers Work in Apache Kafka

In Kafka, "multiple consumers" can mean two completely different things. You can test both in this project right now:

Pattern 1

Fan-Out (Publish-Subscribe)

Different Consumer Groups: Both consumers subscribe to the same topic demo-ping-topic, but each has a different groupId (e.g. planogram-service-group vs audit-service-group).

  • Kafka gives 100% of the messages to Group A AND Group B.
  • Each group tracks its own committed offsets independently in Kafka.
  • Perfect for: Microservices sync, sending notifications, audit logging.
Pattern 2

Load Balancing (Competing Consumers)

Same Consumer Group, Multiple Partitions: Multiple worker threads or service instances share the same groupId.

  • The topic has multiple partitions (e.g. 3 partitions).
  • Kafka balances partitions across workers: Worker 1 takes partition 0, Worker 2 takes partition 1, etc.
  • Each message goes to only one worker in that group (divided labor).
Hands-On Flow 1

How to Add a Second Consumer Group (Fan-Out)

Create an AuditEventConsumer.java in either demo-assets-service or demo-planogram-service: 

@Service
public class AuditEventConsumer {
    private static final Logger log = LoggerFactory.getLogger(AuditEventConsumer.class);

    // Using a different groupId creates a second independent consumer!
    @KafkaListener(topics = "demo-ping-topic", groupId = "audit-service-group")
    public void consume(PingEvent event) {
        log.info("[AUDIT-GROUP] Captured ping event: {}", event.getId());
    }
}
Observation in WebApp: When you click "Publish Ping Event" above, both planogram-service-group and audit-service-group will process the exact same event at the exact same time.
Hands-On Flow 2

How to Enable Multi-Threaded Partition Workers

Step 1: In KafkaTopicConfig.java, increase partitions from 1 to 3: 

@Bean
public NewTopic pingTopic() {
    return TopicBuilder.name(PING_TOPIC)
            .partitions(3)  // 3 partitions
            .replicas(1)
            .build();
}

Step 2: In PingEventConsumer.java, add concurrency = "3": 

@KafkaListener(
    topics = "demo-ping-topic",
    groupId = "planogram-service-group",
    concurrency = "3" // 3 parallel consumer threads for 3 partitions
)
public void consume(PingEvent event, @Header(KafkaHeaders.RECEIVED_PARTITION) int partition) {
    log.info("[Thread: {}] Received event on partition {}: {}",
        Thread.currentThread().getName(), partition, event.getId());
}
Observation in WebApp: Click "Send Batch (3x)" in the tester tab. You'll see 3 messages distributed across the 3 partitions and handled concurrently by different threads in the planogram service logs!
